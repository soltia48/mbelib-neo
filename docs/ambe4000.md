# AMBE+ 4000 bps speech + 2400 bps FEC

**Status: experimental C speech decoding and channel FEC.**
The decoder uses an approximate speech model; sample-exact conformance is not
established. Native speech encoding is not implemented. Do not pass its 80-bit
output to the AMBE 2400/2450 APIs.

The supported format uses rate index 26, with raw speech at index 17. Index 58
has the same nominal rates but uses AMBE+2 and is incompatible.

## Decode audio in software

```sh
cmake --preset dev-debug
cmake --build --preset dev-debug -j
build/dev-debug/ambe4000_decode < input.ambe > output.wav
```

Input is consecutive 16-byte rate-26 channel frames, MSB first, with no packet
headers or radio framing. WAV output is 8 kHz, mono, signed PCM16; each input
frame produces 160 samples. The command buffers PCM before writing the WAV,
rejects trailing partial frames, and reports correction distance and muted
frames on stderr. It does not remove algorithmic delay. No hardware, Python,
model download or network access is needed to build or run the decoder.

For library use:

```c
mbe_ambe4000_decoder *decoder = mbe_ambe4000DecoderAlloc();
if (decoder == NULL) { /* allocation failed */ return -1; }
/* Keep decoder for the entire stream, then free it. */
char channel[128]; /* fill each element with one 0/1 channel bit */
short pcm[160];
mbe_process_result result;
/* ... fill channel from a received 16-byte frame, MSB first ... */
int distance = mbe_processAmbe6400x4000Frame(pcm, &result, channel, NULL, decoder);
/* distance < 0: invalid input; otherwise pcm contains one 20 ms frame */
mbe_ambe4000DecoderFree(decoder);
```

Use one context per stream. Allocation initializes it; `mbe_ambe4000DecoderReset()`
restarts spectral history, overlap and the per-stream noise sequence. Processing
allocates no memory. A context must not be used concurrently without external
synchronization. Invalid pointers/bits preserve PCM, output bits and context.

`mbe_processAmbe4000Data()` accepts 80 **priority-ordered** speech bits without
channel coding. `mbe_processAmbe6400x4000SoftFrame()` accepts soft channel bits.
All three have an `f` suffix variant for mbelib float scale (PCM16 / 7).
The optional `result` is output-only, including for Data calls. To keep channel
error counts when synthesizing, use the combined Frame or SoftFrame API.

The native model uses 0.8 spectral prediction, approximate pitch/HOC/subframe
tables, six overlapping voicing masks and two 80-sample synthesis steps.
Code 124 is muted DTX (`SILENCE|MUTE`), not generated comfort noise. Code 126
supports single-tone, DTMF and call-progress IDs with approximate
amplitude; codes 125/127 and unsupported IDs are muted with `ERASURE`.
`NOTONES=ON` mutes recognized tones too. Special frames clear synthesis overlap
but retain the previous voice model; exact state restoration remains unverified.
There is no speech concealment policy inferred from Viterbi distance alone.

Evaluation of 1,212 frames from four public speech clips produced STOI
0.798–0.885. A two-sentence clip matched the source ASR transcript apart from
letter case. Other clips have recognition errors. See [the model and validation
notes](ambe4000-research.md#independent-native-speech-validation).

## Native channel API

```c
char parameters[80]; /* one binary value (0 or 1) per char, priority order */
char channel[128];   /* one binary value per char, device channel order */
mbe_process_result result;

int distance = mbe_decodeAmbe6400x4000Frame(channel, parameters, &result);
/* Negative: invalid arguments/bits. Nonnegative: selected codeword distance. */
int status = mbe_encodeAmbe6400x4000Frame(parameters, channel);
```

`mbe_decodeAmbe6400x4000SoftFrame()` accepts 128 `mbe_soft_bit` values. Viterbi
branch cost is the sum of the reliabilities of changed bits. The returned error
count is the hard-bit distance to the selected path, including the tail. Ties
use deterministic predecessor order. Neither distance zero nor a unique path
certifies that the original speech bits were recovered.

Each 20 ms frame contains 80 speech bits and 48 bits of redundancy:

- Priority bits 0–35 are convolutionally encoded, with six zero tail bits.
- The encoder has constraint length 7 and two polynomials, `0x4f`, then `0x6d`.
  Shift left and insert the newest input bit in bit 0, starting from zero.
  The output is 42 pairs (84 bits).
- Priority bits 36–79 are appended unchanged (44 bits, **no error protection**).
- Interleave the resulting 128 bits by filling columns of a ragged 12-row
  matrix: the first eight rows have 11 columns; the last four have 10.
  Reading rows gives device channel order. Pack each group of eight bits MSB
  first to obtain a 16-byte rate-26 channel frame.

Raw rate-17 bytes are also interleaved. For 80 bits, use eight rows of 7 columns
and four rows of 6 columns. `tools/ambe4000/thumbdv.py` provides `pack_raw()` and
`unpack_raw()` for this mapping. The native FEC data API uses **priority order**,
not unpacked rate-17 wire order. No radio-specific TCH ordering, scrambling or
transport framing is included.

These channel entry points validate bits and pointers, preserve output on invalid
input, and allocate no memory. Decode initializes an optional result, setting
`protected_errors` and `total_errors`; C0 and C4 are not separate codewords here.
Soft decode additionally sets `MBE_PROCESS_FLAG_SOFT_INPUT`. The selected path
may be wrong when errors exceed the code's correction capability; the API does
not invent an uncorrectable-frame or speech-quality flag.

## Optional hardware audio tools

The Python tools can encode or decode through a compatible serial device.
They require Python 3, pyserial and exclusive serial-port access. The default
configuration is 460800 baud, 8N1. These tools are separate from the native
software decoder.

```sh
# Input must be 8 kHz, mono, signed PCM16 WAV.
python3 tools/ambe4000/codec.py encode --device /dev/ttyUSB0 \
  --input speech.wav --out build/ambe4000/my-encoded

# Input is consecutive 16-byte rate-26 frames, without packet headers.
python3 tools/ambe4000/codec.py decode --device /dev/ttyUSB0 \
  --input build/ambe4000/my-encoded/audio.ambe --out build/ambe4000/my-decoded
```

Output directories must be new. Encoding pads the final PCM frame and appends
three zero frames by default (`--flush-frames 0..10`); algorithmic delay is not
removed. Decoding writes 160 samples per channel frame to `audio.wav` and
records decoder status in `frames.jsonl`. A successful process and
`DATA_INVALID=0` do not establish speech intelligibility.

`manifest.json` records device identity, frame counts and control exchanges.
A failed conversion leaves an `incomplete` manifest and any partial output for
diagnosis. The tools set volatile codec controls, unity PCM gain, and disable
tone detection, DTX, noise suppression and echo processing. They leave the
selected mode active; another application should configure it before use.
No firmware or EEPROM writes are performed.

## Parameter layout and validation

[The model notes](ambe4000-research.md) describe the 80-bit layout, spectral
prediction, subframe synthesis, supported special frames and remaining limits.
The checked-in model tables are sufficient for normal builds; no external
model files or numerical Python packages are needed at runtime.

`tests/data/ambe4000_vectors.h` contains 27 synthetic reference vectors, each
with logical parameter bytes, raw rate-17 bytes and protected rate-26 bytes.
Tests flip every channel bit in every vector, check all 84 protected and all
44 unprotected positions, exercise soft correction of a seven-bit weak-confidence
burst, and validate bad input. Speech tests cover state reset, independent
contexts, processing-path agreement, tone frequency/level and arbitrary frames.
